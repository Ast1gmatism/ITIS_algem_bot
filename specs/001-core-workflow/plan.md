# 001 — План реализации

## Инкременты

1. **M1, текущий:** доменное ядро, прикладные операции, атомарное JSON-хранилище, порт ведомости с in-memory адаптером, чистые представления двух зон, offline-демо и автотесты.
2. **M2, следующий:** aiogram-адаптер общего табло и личной панели, callbacks с проверкой сессии/прав, фоновые таймеры, доставка одного общего пинга.
3. **M3, после проверки схемы:** Google Sheets-адаптер, реальные заголовки и сопоставление строк, debounce/периодический Pull, проверка с тестовой таблицей.
4. **Размещение:** после выбора хостинга. Не является выполненным этапом M1.

## Организация кода

Используется `src/algem_bot/` вместо набора модулей в корне: это техническая упаковка тех же ответственностй, удобная для установки, изолированных импортов и CI.

- `models.py`: Pydantic v2, строгие данные и инварианты.
- `config.py`: параметры и доверенные начальные администраторы без секретов.
- `engine.py`: чистые баллы, категории и правила допуска с явным временем.
- `service.py`: операции пары и регистрации.
- `storage.py`: репозиторий, одна защищённая транзакция изменения, атомарная запись.
- `ports.py`, `sheets_sync.py`: контракт ведомости и согласование ревизий.
- `adapters/memory_sheet.py`: только offline-адаптер, не Google API.
- `views.py`: транспортно-независимые представления.
- `demo.py`: воспроизводимый сценарий без сети и настоящих данных.

Время передаётся через часы; тесты не используют реальные ожидания 20/60 секунд.

## Идентичность

Внутренний строковый ID существует в модели и тестовом порте. Он не требует действий внесистемного и не фиксирует физическую колонку таблицы. Реальное сопоставление строк будет выбрано в M3 после осмотра схемы.

TG_ID — уникальная необязательная связь. Регистрация требует одобрения; bootstrap allowlist не превращается в отдельного студента с вымышленными выходами. Для уже привязанного аккаунта явная роль ведомости имеет приоритет над bootstrap; снятие роли не обходится локальной настройкой.

## Транзакции и синхронизация

- Repository держит state-lock только на локальном изменении и его сохранении.
- Операция работает с копией; неудача валидации/сохранения не публикует частичное состояние.
- Координатор ведомости держит отдельный sync-lock на цикл, но не state-lock во время I/O.
- Для каждого ожидающего сырого поля сохраняются база, желаемое значение, ревизия и попытки отправки.
- Подтверждение записи относится к конкретной ревизии, а не ко всем последующим изменениям поля.
- Ручная внешняя правка относительно известной базы приоритетна. Прошлая база и распознанная собственная попытка не выдаются за новую ручную коррекцию.
- Производные баллы/категория пересчитываются, а не считаются источником исходных данных.

Ограничение: не обнаружить ручную правку в то же число и не обеспечить глобальную транзакцию с браузерным редактором обычными Sheets-запросами. Это остаётся явно задокументировано.

## Технические значения без новых пользовательских процессов

- Защитный предел оценки 0–10 следует исходному максимуму, не создаёт отдельный режим внесистемного-лидера.
- Смена роли на внесистемную или удаление TG-привязки снимает недопустимую активную бронь; изменение одной категории её не отменяет.
- В представлении подпись `своб. x/y` означает свободные подпункты из общего числа.
- Тесты используют исключительно синтетические ФИО и TG_ID.

## Проверка

Тесты на Python 3.11–3.13 через CI; локально — доступный Python 3.13. Проверки не требуют сети и секретов после установки зависимостей. Команды будут добавлены в README по завершении M1.
