# Решения контрольных вопросов

**Версия документации:** 0.2.  
**Дата:** 19 ноября 2026 года.  
**Статус:** фиксация ответов владельца продукта до начала реализации.

Документ дополняет [спецификацию](SPEC.md). Он разделяет явно выбранные правила, сохранённые исходные параметры и ещё не утверждённые технические детали.

## 1. Согласованные продуктовые решения

| ID | Решение | Следствие |
| --- | --- | --- |
| D-01 | Главная цель — удобное занятие номеров и снижение нагрузки на ответственных | Не добавлять ручные действия ради обслуживания аналитики и ограничений |
| D-02 | `N_max` считается только по активным: `Студент` и `Админ` | `Внесистемы` не влияют ни на максимум, ни на среднее |
| D-03 | Две зоны: бронь в общем чате и личная админ-панель | Подтверждения и показатели для ответственного не размещаются как рабочие админские кнопки в общем табло |
| D-04 | Сначала отдельное окно для 🟢, длительность — 20 секунд | Во время окна 🟡 и 🔴 ждут; если нет зарегистрированных 🟢, способных взять бронь, окно пропускается |
| D-05 | Ручной лок/тумблер 🔴 убрать как лишнюю нагрузку | Остаются автоматические условия доступа; ответственный не обслуживает блокировки вручную |
| D-06 | Выбор ФИО + подтверждение ответственного | До одобрения привязки студент не может бронировать от имени выбранного человека |
| D-07 | `Внесистемы` не нужно привязывать к Telegram и брони | Они остаются в ведомости, а ответственный может выбрать их по ФИО и засчитать фактическую сдачу |
| D-08 | Выход подтверждает только ответственный | Студенческий клик и регистрация сами по себе не начисляют выход |
| D-09 | Google Таблица — источник правды и приоритет | Ручное число считается итогом, уже учитывающим выходы; при обнаруженном конфликте нельзя дополнительно прибавлять к нему уже учтённый локальный выход |
| D-10 | Отдельная отмена сдачи в первой версии не нужна | Ошибочный счётчик исправляется в таблице; статус подпункта автоматически не восстанавливается |
| D-11 | Один общий пинг приоритетным на новую порцию задач | Нет отдельных сообщений на каждый клик и серии личных пингов |
| D-12 | Постоянный хостинг не выбран | На текущем этапе не создавать сервер, подписку или обязательную инфраструктуру размещения |

## 2. Пояснение про студентов без Telegram

Ответ владельца продукта: «Просто не вяжем внесистемных к ТГ и брони, но считаем их, если они выходят».

Это означает:

- запись человека в ведомости существует независимо от регистрации в боте;
- `TG_ID` не может быть обязательным полем для всех строк;
- фактическую сдачу можно назначить человеку без Telegram-привязки;
- участие в максимуме и среднем определяется статусом, а не наличием `TG_ID`;
- отсутствие `TG_ID` у активного студента само по себе не превращает его во `Внесистемы`.

Способ внутренней идентификации записей — техническая задача. Из этого ответа не следует согласие на обязательное добавление отдельной служебной колонки в существующий лист.

## 3. Баллы внесистемных: граница ответа

На вопрос о гипотетическом превышении активного максимума внесистемным участником владелец ответил: «Не может — они выходят редко, на то и внесистемные».

Фиксируется ожидаемое поведение реальной группы: внесистемные не являются лидерами по числу выходов. Не требуется выделять этот случай в отдельный пользовательский процесс или дополнительную настройку.

Не выбраны и не считаются утверждёнными отдельные варианты «всегда прочерк вместо баллов» либо специальная формула исключительно для внесистемных. В обычном случае действует исходная формула. Общий исходный предел — 10 баллов; численная защита остаётся инженерной задачей без нового ручного процесса.

## 4. Исходные параметры, которые не менялись

- Анти-тишина: 60 секунд после публикации задач или последней успешной брони.
- Порог планового допуска 🔴: разрыв с активным средним не более 0.5.
- Pull ведомости: каждые 30 секунд и по `/sync`.
- Debounce Push: 1.5 секунды.
- Обычное подтверждение: +1 выход.
- Нестандартные начисления: поправка итогового числа в таблице.
- Одна бронь на человека; автовыбор первой свободной буквы.
- `/clear` не обнуляет выходы.

После удаления ручного тумблера базовое автоматическое поведение следует из таймера: новая успешная бронь запускает отсчёт заново, а плановый доступ зависит от текущего разрыва со средним. Это не новое ручное действие.

## 5. Что ответы пока не определяют

- Точную физическую схему и вкладку существующей Google Таблицы; добавление служебной колонки не подтверждено.
- Конкретные `TG_ID` первых ответственных и ID разрешённого чата.
- Точный вид подписей кнопок и компактную раскладку личной панели.
- Способ постоянного размещения.
- Полный протокол обнаружения внешних изменений Google Sheets: приоритет таблицы согласован, транзакционные гарантии API из него не следуют.

Эти детали не следует выдавать за выбранные пользователем варианты. Часть решается при техническом проектировании, а доступы и структура листа уточняются до подключения реальных сервисов.
